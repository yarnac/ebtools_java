= AI-Service API-Dokumentation
:toc: preamble
:toclevels: 3
:sectnums:

== Überblick

Diese API bietet einen einheitlichen Zugriff auf mehrere Large Language Model-Provider (LLM) wie Ollama, OpenAI und Anthropic. Sie abstrahiert die spezifischen API-Details und ermöglicht die Ausführung von Anfragen mit Texten und Bildern über eine gemeinsame Schnittstelle.

Das System ist modular aufgebaut:

* API-Ebene für Anfragen und Antworten (`.api`)
* Client-Factory und Modell-Management (`.infrastructure`)
* Content-Mapping zur JSON-Serialization (`.contentmapping`)
* Spezielle Klassen für jeden Provider (`.ollama`, `.openai`, `.anthropic`)

== Hauptkomponenten

=== Konfiguration

[[AiServiceConfig]]
==== AiServiceConfig

Stellt zentrale Konfigurationswerte bereit und lädt diese aus einer INI-Datei.

[cols="2,3"]
|===
| Methode | Beschreibung
| `current()` | Gibt die Singleton-Instanz zurück

| `getData1()`/`getData2()` | Frei definierbare Datenwerte
| `getTokenFileName()` | Dateiname für Token-Logs
|===

[cols="2,3"]
|===

|===

[cols="2,3"]
|===

|===

=== Requests und Nachrichten

[[LlmRequest]]
==== LlmRequest

Repräsentiert eine Anfrage an ein LLM, bestehend aus Modellname, Nachrichten und Parametern.

[cols="2,2,3"]
|===
| Attribut | Typ | Beschreibung
| `model` | `String` | Name des zu verwendenden Modells (z.B. `qwen3.5:9b`)
| `messages` | `List<LlmMessage>` | Liste der Nachrichten in der Chat-History
| `parameters` | `List<Parameter>` | List der zusätzlichen Parameter (z.B. `temperature`)
| `contentMemo` | `String` | Menschenlesbare Zusammenfassung
| `requestId` | `Long` | Eindeutige ID für Speicherung (wird zur Laufzeit gesetzt)
|===

[cols="2,3"]
|===
| Methode | Beschreibung
| `builder()` | Beginnt einen Builder zur Erstellung einer Anfrage
| `addUserMsg(message)` | Fügt eine `user`-Nachricht hinzu
| `addResponse(response)` | Fügt eine `assistant`-Antwort zur History hinzu
| `addParameter(parameter)` | Fügt einen Parameter hinzu
| `getParameter(name)` | Einen Parameter anhand seines Namens zurückgeben
| `getAllMessageString()` | Konkateniert alle Nachrichteninhalte als String
|===

[[LlmMessage]]
==== LlmMessage

Repräsentiert eine Nachricht mit Text- und/oder Bildinhalten in einem definierten Rollen-Format (`system`, `user`, `assistant`).

[cols="2,2,3"]
|===
| Attribut | Typ | Beschreibung
| `role` | `String` | Rolle der Nachricht (`system`, `user`, `assistant`)
| `contentParts` | `List<ContentPart>` | Liste der Inhalte (`Text`, `Bild`)
| `messageInfo` | `LlmMessageInfo` | Metadaten zur Verarbeitung (Tokens, Zeit usw.)
| `imageFileNames` | `List<String>` | Intern: Liste der Bildpfade
| `textFileNames` | `List<String>` | Intern: Liste von Textdateien
|===

[cols="2,3"]
|===
| Methode | Beschreibung
| `addText(text)` | Fügt einen reinen Text hinzu
| `addImageFromPath(path)` | Fügt ein Bild aus einer lokalen Datei hinzu
| `addImage(mimeType, data)` | Fügt ein Bild mit MIME-Typ und Base64-Daten hinzu
| `getMessageString()` | Menschenlesbare Darstellung der Nachricht
|===

[[LlmRequestBuilder]]
==== LlmRequestBuilder

Fluenter Builder zur Erstellung von `LlmRequest`-Instanzen.

[cols="2,2,3"]
|===
| Methode | Return-Typ | Beschreibung
| `addSystemMsg(msg)` | `LlmRequestBuilderUserMsg` | Fügt eine System-Nachricht hinzu
| `addUserMsg(msg)` | `LlmRequestBuilderUserMsg` | Fügt eine User-Nachricht hinzu
| `addUserMsgWithImage(msg, imagePath)` | `LlmRequestBuilderUserMsg` | Fügt eine Nachricht mit einem Bild hinzu
| `addRequestMsg(msg)` | `LlmRequestBuilderUserMsg` | Fügt `<<system>>` und `user`-Msg hinzu (falls `<<...>>` im Text enthalten)
| `setModel(model)` | `LlmRequestBuilderFinish` | Setzt das Modell
| `addParameter(name, value)` | `LlmRequestBuilderFinish` | Fügt einen Parameter hinzu
| `build()` | `LlmRequest` | Erstellt die finale Anfrage
|===

[[LlmClient]]
==== LlmClient

Zentrale API für die Ausführung von Anfragen.

[cols="2,3"]
|===
| Methode | Beschreibung
| `sendRequest(request)` | Übergibt die Anfrage an den passenden Provider-Client
|===

[cols="2,3"]
|===

[cols="2,2,3"]

[[ContentPartToMapMapper]]
==== ContentPartToMapMapper (Interface)

Definiert den Mapper von `ContentPart` zu einem `Map<String, Object>` für die JSON-Serialisierung.

[cols="2,3"]

|===

[[JsonFileAppendUtil]]
==== JsonFileAppendUtil

Utility zum Hinzufügen von Dateiinhalten zu einem Text über spezielle Marker (`<$ Dateiname`, `<$D Verzeichnis`, etc.). Enthält Sicherheitsprüfungen (Pfadvalidierung).

*Marker-Beispiele:*

* `<$ /home/user/config.json` → Dateiinhalt wird eingefügt
* `<$D /home/user/docs` → Alle Dateien im Verzeichnis werden eingefügt
* `<$DA /home/user/docs` → Rekursiv alle Dateien
* `<$P /home/user/image.png` → Bild wird als Base64 eingefügt

*Hinweis:* Der Code ist auf Thread-Sicherheit, Performance und Fehlerbehandlung optimiert.

[[LlmRequestJsonMapper]]
==== LlmRequestJsonMapper

Transformiert eine vollständige `LlmRequest` in einen JSON-String, passend zur Zielp-API.

[cols="2,3"]
|===
| Methode | Beschreibung
| `getJsonString(request)` | Erstellt den finalen JSON-Body für die API
|===

*JSON-Struktur:*

* Modellname wird direkt eingefügt
* Systemnachrichten werden ggf. separat gesendet (je nach API)
* Nachrichten und Parameter werden gemäß API-Standard serialisiert

== Verwendung der API

=== Einfache Textanfrage (Ollama)

[source,java]
----
String result = LlmRequestService.sendSimpleRequest("Was ist Java?", "qwen3.5:4b", "127.0.0.1");
----

=== Bildanfrage mit JSON-Antwortformat

[source,java]
----
LlmRequest request = LlmRequest.builder()
    .addUserMsgWithImage("Analysiere das Bild", "/path/to/image.jpg")
    .setModel("qwen3-vl:30b")
    .addParameter("temperature", 0.0)
    .build();

LlmResponse response = LlmRequestService.sendRequest(request);
String answer = response.getAnswer();
----

=== Anfrage speichern und später wiederverwenden

[source,java]
----
// Speichern
LlmRequestManager manager = LlmRequestManager.current();
manager.store(request);

// Wiederverwenden
LlmRequest retrieved = manager.getLlmRequest(request.getRequestId());
----

== Modellkonfiguration

Die Modelle werden in einer Textdatei (Konfigurationspfad von `AiServiceConfig.getModelFileName()`) verwaltet:

[cols="2,2,3"]
|===
| Hersteller | Modell | Beschreibung
| `ollama` | `qwen3.5:4b` | Qwen3.5 mit 4 Mrd. Parametern
| `ollama` | `qwen3.5:9b` | Qwen3.5 mit 9 Mrd. Parametern
| `ollama` | `qwen3-vl:30b` | Multimodales Qwen3 Vision-Modell
| `openai` | `gpt-5.6-luna` | OpenAI-GPT-Modell
| `anthropic` | `claude-haiku-4-5` | Anthropic Claude Haiku
|===

== Sicherheit

* API-Schlüssel werden verschlüsselt in einer Datei gespeichert (`getGeheimnisFileName()`), genutzt wird ein Twofish-Verfahren.
* Pfade für Dateieinblendungen werden auf `allowedPaths` geprüft (siehe `JsonFileAppendUtil`).
* Host-Adressen für Ollama werden nicht direkt aus dem Code abgeleitet, sondern dynamisch ermittelt.

== Hinweise

* Der `OllamaClient` nutzt `CompletableFuture` für Host-Ermittlung und Prüfung.
* `ContentPart` und `ContentPartToMapMapper` sind sehr spezifisch für die jeweiligen APIs gestaltet.
* Die `ContentPartMapperAnthropic` sendet `system`-Nachrichten separat, andere APIs nicht.
* Die `LlmResponse` berechnet `totalTokens` und `tokensPerSecond` automatisch bei Bedarf.

== Beispiel-Anwendungen

=== Bildverschlagwortung

[source,java]
----
public String getImageDescription(String userMessage, String image, String model) {
    LlmRequest request = LlmRequest.builder()
        .addUserMsgWithImage(userMessage, image)
        .setModel(model)
        .addParameter("temperature", 0.0)
        .build();
    LlmClient client = new LlmClient();
    LlmResponse response = client.sendRequest(request);
    return response.getAnswer();
}
----

=== Übersetzungsdienst

[source,java]
----
String systemMsg = "Du bist Türkisch Deutsch Übersetzer";
String userMsg = "Übersetze '%s' von Türkisch nach Deutsch.".formatted(word);
LlmRequest request = LlmRequest.builder()
    .addSystemMsg(systemMsg)
    .addUserMsg(userMsg)
    .setModel(model)
    .addParameter("temperature", 0.0)
    .build();
----

=== Wörterbuchdienst

[source,java]
----
String systemMsg = "Du bist %s Deutsch Übersetzer".formatted(sprache);
String userMsg = "Übersetze das Wort '%s' von '%s' nach Deutsch. Liefere nur die deutschen Übersetzungen im Format Übersetzung1|Übersetzung2.";
----

== Zusammenfassung

Die API stellt ein flexibles und erweiterbares System für den Zugriff auf LLMs bereit. Die strikte Trennung in API-Schicht, Factory und Provider-Implementierungen ermöglicht einfaches Hinzufügen neuer Modelle und Anbieter. Die integrierte Speicherung, Log-Funktion und Content-Mapping-Schicht machen die API für produktiven Einsatz geeignet.
