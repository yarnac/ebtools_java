# DoubleFinder / Duplicate Finder – AsciiDoc Dokumentation

== 1. Projektübersicht

Das Projekt *DoubleFinder* (auch *Duplicate Finder* genannt) ist eine Java-Swing-Anwendung zur Erkennung und zum Umgang mit Duplikatdateien in Verzeichnissen. Es existieren zwei Implementierungsgenerationen:

* **Legacy** (Paket `com.eb.doubletten`) – die ältere, monolithische Version mit fest codierten Verzeichnissen und Verknüpfung von View und Controller.
* **Refactored** (Paket `com.eb.doubletten.actual`) – die neuere, modularisierte Version mit sauberer Trennung in View, Controller, Repository und Service-Ebene.

Beide Generationen nutzen die Bibliothek `com.eb.base` für GUI-Dekoration, INI-Datei-Handling und Datei-Utilities.

==== 4.3.4 Filterlogik

* **Positivfilter** (`isAllowedDoublette`): Leertext → alles erlaubt. Sonst werden Begriffe per Leerzeichen getrennt. Ein Präfix `+` bedeutet *Muss-enthaltene* (AND-Logik, `return false` bei Nichteintreffen). Ohne Präfix gilt OR-Logik.
* **Negativfilter** (`isForbiddenDoublette`): Leertext → nichts ausgeschlossen. Sonst wird jeder Leerzeichen-getrennte Begriff geprüft; ein Treffer schließt das Duplikat aus.

==== 4.3.5 Auto-Play

`switchAutoPlay()` erzeugt bei Erstaufruf einen `Timer` (Daemon) mit `scheduleAtFixedRate` in 3500 ms Intervall. Ein zweiter Aufruf stoppt den Timer. `nextAfter500MS` wird über `onActivate` (Window-Focus-Gain) ausgelöst und ruft nach 1 s `next()` auf.

==== 5.5.3 FilenameDuplicateScanService

* Durchläuft `Files.walk(root)`, filtert Regular Files.
* Gruppierungsschlüssel = `path.getFileName().toString()`.
* `isAllowedFile` schließt Pfade aus, die `\\bin\\`, `/bin/`, `\\obj\\`, `/obj/` enthalten.
* Duplikat = Gruppe mit `size > 1`.

==== 5.5.4 SizeHashcodeDuplicateScanService

* Verwendet `FileHashcodeWithCacheService` als Hashquelle.
* Gruppierungsschlüssel = Hash-String.
* `isAllowedFile` schließt zusätzlich leere Dateien und `.ebindex` aus.
* Ergebnis wird nach Label (Hash) sortiert.

==== 5.6.2 FileHashcodeService

Berechnet einen SHA-256-Hash durch *Teilsampling*:

[cols="3,3,5"]
|===
| Schritt
| Buffer-Größe
| Beschreibung

| Anfang
| `bufferSize` (Default 64 KiB)
| Erste Bytes der Datei

| Mitte
| `bufferSize`
| Mitte der Datei, nur wenn `length > 2 * bufferSize`

| Ende
| `bufferSize`
| Letzte `bufferSize` Bytes der Datei
|===

* `getFullHashCode(Path)` liest die *gesamte* Datei in 8 KiB-Blöcken.
* `bytesToHex` konvertiert den Digest in eine hexadezimale Zeichenkette.
* Bei Ausnahme wird `"<keine>"` zurückgegeben.

== 9. Zusammenfassung

Das Projekt durchläuft eine klare Evolution von einer monolithischen, hart codierten Swing-Anwendung hin zu einer schichtengetrennten Architektur mit Strategy-Pattern für den Scan, separatem Repository und INI-persistierter Konfiguration. Die Legacy-Version bietet umfangreiche interaktive Funktionen (Filter, Auto-Play, Tastenkürzel, Verschieben/Kopieren), die in der Refactored-Version noch nicht vollständig portiert sind. Die Hash-Berechnung mit Teilsampling und Caching stellt sicher, dass große Verzeichnisse in akzeptabler Zeit gescannt werden können.
